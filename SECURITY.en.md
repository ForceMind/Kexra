# Kexra Security Policy

Report vulnerabilities **in the Kexra software itself** via [GitHub Security](https://github.com/ForceMind/Kexra/security) **if private vulnerability reporting is enabled**. Otherwise first establish a trusted private channel with the repository owner; do not put exploit details, client information, real API keys, or personal data into a public GitHub issue.

Useful report details: affected commit/version, preconditions, sanitized reproduction, expected versus actual behavior, impact, and suggested mitigation. There is currently no published SLA, guaranteed support window or bug bounty.

Only run this software on systems you own or have explicitly been authorized to assess, preferably in an isolated lab. Existing application-level approval/interception mechanisms do not constitute a hardened sandbox; release and auto-update pipelines have not yet completed validation after the rebrand.

See the canonical [Chinese policy](SECURITY.md) and [security model](docs/SECURITY_MODEL.md).
