# 更新与回滚：实现、验证与边界

当前没有正式 Kexra Release。以下说明用于开发、隔离演练和后续发布验收，不代表生产升级已经完成验证。

## 原生二进制流程

1. 从固定 `ForceMind/Kexra` 发布源查询正式版本；拒绝草稿、预发布和不可比较的版本。
2. 按当前 OS/架构查找 ZIP 和 `SHA256SUMS`，仅接受 HTTPS GitHub 更新域名；拒绝 URL 内凭据和非标准 HTTPS 端口。
3. 下载压缩包，核对 SHA256，只提取唯一普通可执行文件，并以 `-h` 冒烟测试。
4. 在程序目录暂存 `.new`、独立校验和及有效升级标记。标记不能可靠保存时取消更新。
5. 当前进程请求重启（退出码 75），守护脚本重新启动旧程序；Bootstrap 再次验证并备份/换装，然后再次重启。
6. 新程序启动累计次数；稳定后由 Settle 确认。连续三次初始化失败，下次 Bootstrap 尝试自动回滚；计数无法持久化时立即尝试回滚。

压缩包最多 512 MiB、解压二进制最多 512 MiB、Release 元数据最多 2 MiB、校验清单最多 1 MiB。长度未知的响应仍受硬上限限制；超长清单不能截断后当作成功。重复校验条目、同名资产及多个二进制条目均拒绝。

标记先在同目录临时文件完整写入、Sync、Close，再替换旧记录（权限 0600）。这不等于已经完成断电、目录持久化或所有文件系统故障演练。空 JSON、错误版本和越界计数不授予换装权限；兼容旧记录的零时间戳。

## 回滚与恢复

底层手动回滚会先检查上一版本可执行性，再交换当前程序与备份，可再次切回。自动回滚安装旧程序失败时尝试把当前程序恢复到原路径；双重恢复失败明确报告，并保留备份与 `.failed` 文件供人工恢复。目录和特殊文件不能作为备份安装。

只恢复二进制**不会恢复数据库或用户配置**。本更新器不生成数据库/JWT/自定义 Skills 的备份，也不验证任意未来版本的数据迁移可逆性。发布前必须在副本上验证新旧程序与数据/配置兼容；若新版启动改动了数据库，回退二进制不能代替数据恢复。

自动更新当前只提取可执行文件，ZIP 中的 Skills 等附带资源不会随之同步安装。不能据此宣称完成了整个安装目录迁移。

## Docker 路径

容器中的二进制替换只写入容器可写层；重建容器会回到镜像携带的版本。持久升级/回退应使用经过验收的镜像，并按 [部署说明](DEPLOYMENT.md) 保留数据卷、JWT 私有卷和自定义 Skills。原生二进制演练不能代替 Docker 镜像升级或旧容器密钥恢复演练。
