# Kexra 安全边界与威胁模型

Kexra 整合智能体、第三方模型、扩展工具及流量记录，属于**需要严格隔离与授权**的高风险软件类别。此文件不应被理解为对现有实现的安全认证。

## 基本原则

1. 仅对自有或取得明确授权的资产进行测试，并保留书面范围、有效期及联系人。
2. 默认使用本地/实验室网络，禁止跨越授权范围访问外网或业务系统。
3. 由具备权限的人类审核高风险操作；自动审批规则与工具内 `guard` 不是硬安全边界。
4. 外部网页、日志、模型回复、MCP 工具返回内容均视为不可信输入。
5. 所有报告结论都应可追溯原始证据，禁止 AI 将推测写成已验证事实。

## 主要风险及防御要求

| 风险 | 防御要求 |
| --- | --- |
| Prompt Injection | 区分来自用户的授权指令与工具/网页等不可信输入 |
| 越权工具调用 | 按任务隔离凭据和工具权限，限制允许执行的命令与目标 |
| SSRF / 非授权外联 | 使用网络策略限制域名、IP、网段、重定向与代理 |
| 数据泄露 | 秘钥遮盖、最小权限、受控保留与加密备份 |
| 供应链与自动更新 | 审查模型/包/镜像来源，使用固定可信版本和校验 |
| 无意扩大攻击面 | 对管理 API、代理端口和数据库做严格网络访问控制 |
| 伪阳性/证据污染 | 保存原始日志与取证信息，人工复核漏洞严重性 |
| 模型/工具费用异常 | 模型额度、并发、任务时长、日志量上限和告警 |

## 当前实现状态

- 项目具备操作拦截和审批相关模块，但**不能认定**为强制隔离沙箱。
- 部分旧版本安全规则可配置/关闭；生产前应复核系统级控制是否独立于 Agent。
- 新的 `selfupdate` 目标是 `ForceMind/Kexra`，在正式 Release 未验证前不得依赖 UI 一键更新。
- 仍有兼容字段与历史提示词、通知文案、检测样例；不能通过全局字符串替换消除安全风险。
- 接口、端口、容器镜像均未在本次文档整理中完成生产环境测试。

## 事件响应

发现疑似泄露、RCE、SSRF、绕过审批或私有密钥暴露时，应暂停相关环境使用、保存必要的最小化证据、轮换受影响凭据、在隔离副本排查。**不要将真实密钥、可利用的客户数据或攻击详情发到公开 Issue。**

漏洞私下报告渠道与维护者承诺见 [SECURITY.md](../SECURITY.md)。若当前 GitHub 私有漏洞报告功能不可用，请先与仓库所有者建立可信的非公开联系方式。
