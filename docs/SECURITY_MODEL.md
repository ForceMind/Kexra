# Kexra 安全边界与威胁模型

Kexra 整合智能体、第三方模型、扩展工具及流量记录，属于**需要严格隔离与授权**的高风险软件类别。此文件不应被理解为对现有实现的安全认证。

## 基本原则

1. 仅对自有或取得明确授权的资产进行测试，并保留书面范围、有效期及联系人。
2. 默认使用本地/实验室网络，禁止跨越授权范围访问外网或业务系统。
3. 由具备权限的人类审核高风险操作；自动审批规则与工具内 `guard` 不是硬安全边界。
4. 外部网页、日志、模型回复、MCP 工具返回内容均视为不可信输入。
5. 所有报告结论都应可追溯原始证据，禁止 AI 将推测写成已验证事实。

## 主要风险及防御要求

| 风险 | 防御要求 |
| --- | --- |
| Prompt Injection | 区分来自用户的授权指令与工具/网页等不可信输入 |
| 越权工具调用 | 按任务隔离凭据和工具权限，限制允许执行的命令与目标 |
| SSRF / 非授权外联 | 使用网络策略限制域名、IP、网段、重定向与代理 |
| 数据泄露 | 秘钥遮盖、最小权限、受控保留与加密备份 |
| 供应链与自动更新 | 审查模型/包/镜像来源，使用固定可信版本和校验 |
| 无意扩大攻击面 | 对管理 API、代理端口和数据库做严格网络访问控制 |
| 伪阳性/证据污染 | 保存原始日志与取证信息，人工复核漏洞严重性 |
| 模型/工具费用异常 | 模型额度、并发、任务时长、日志量上限和告警 |

## 当前实现状态

- 项目具备操作拦截和审批相关模块，但**不能认定**为强制隔离沙箱。
- 部分旧版本安全规则可配置/关闭；生产前应复核系统级控制是否独立于 Agent。
- 新的 `selfupdate` 目标是 `ForceMind/Kexra`，在正式 Release 未验证前不得依赖 UI 一键更新。
- 仍有兼容字段与历史提示词、通知文案、检测样例；不能通过全局字符串替换消除安全风险。
- 接口、端口、容器镜像均未在本次文档整理中完成生产环境测试。

## 事件响应

发现疑似泄露、RCE、SSRF、绕过审批或私有密钥暴露时，应暂停相关环境使用、保存必要的最小化证据、轮换受影响凭据、在隔离副本排查。**不要将真实密钥、可利用的客户数据或攻击详情发到公开 Issue。**

漏洞私下报告渠道与维护者承诺见 [SECURITY.md](../SECURITY.md)。若当前 GitHub 私有漏洞报告功能不可用，请先与仓库所有者建立可信的非公开联系方式。

## 工作空间文件边界的已验证范围

PR #17 的工作空间列表、读取、下载、写入、上传、建目录、删除，以及聊天附件创建/上传统一通过 Go 1.26.9 的 [`os.Root`](https://github.com/golang/go/blob/go1.26.9/src/os/root.go)。不能只对字符串或解析后的符号链接做检查，再使用原始绝对路径打开文件；下载必须使用已经受限的文件句柄。Linux 与 Windows 原生回归、正常文件生命周期和原始二进制证据保留的结果见 [工作状态](WORK_STATUS.md)。

相对且位于根目录内的符号链接继续工作；绝对或越界链接被拒绝。该边界只约束这些文件 API，不能阻止具备更高权限的 Agent/Bash/MCP 直接访问系统，也不隔离 bind mount、设备文件和既有硬链接。JWT 和管理员初始化的边界见下文；工具授权和出站策略仍需各自验证，不以文件 API 修复替代。

## 认证与密钥启动边界（开发中）

管理员首次初始化由 PostgreSQL 单条条件写入竞争：仅不存在或为空的密码设置可被写入，已有非空密码不会被初始化请求覆盖。只有成功写入的请求获得 Token；读取或保存失败均拒绝初始化。该保证跨 Server 实例和连接池，不依赖单进程互斥锁；不改变已有账号、密码哈希、JWT 或新旧 Cookie 兼容，也不需要修改数据库结构。它不提供首次安装时的人类身份核验，管理入口仍须受控开放。

JWT 专用目录检查基于已经打开的工作目录实际身份，逐段固定目录句柄；密钥读取、创建、发布和旧路径清理均绑定目录句柄。现有目录在打开前后核对身份，密钥文件拒绝符号链接和非普通文件；并发首次启动不覆盖其他启动已发布的密钥。每次启动都重新核对遗留副本，相同内容才清理，冲突或失败拒绝静默继续。配置与兼容约束见 [配置](CONFIGURATION.md)。

这些约束依赖可信父目录、挂载和操作系统访问控制。具备父目录重命名权限的进程仍能移动已打开目录；本实现不隔离既有硬链接、bind mount、同权限进程或高权限工具。Windows ACL、断电恢复和实际旧生产实例升级仍需独立验收，不能用单元测试替代。验证范围与未执行的 PostgreSQL/跨平台检查以 [工作状态](WORK_STATUS.md) 为准。


## 远程 MCP 与通知出站（开发分支）

远程 MCP 配置凭据和会话仅发送到同一协议、主机和有效端口；legacy SSE 从完整 endpoint 事件读取同源 POST 地址，日志 data 不参与地址发现，帧按线上字节有界读取。通知保留现有地址策略，并拒绝任意一跳 HTTPS 降级；非法 Location 原文不进入投递错误。细节与兼容变化见 [出站边界](OUTBOUND_SECURITY.md)。

该边界保护请求来源，不是全局目标授权、DNS/代理沙箱或工具权限隔离。当前仅以真实 HTTP 客户端加内存传输验证，真实网络/完整 SDK 与生产路径未验收；认证 PR #19 和完整镜像 PR #15 仍保持独立发布门禁。


## 工具策略读取故障（开发分支）

拦截规则和启用集合的加载/匹配错误立即形成平台阻断，不能当作关闭拦截或没有规则。两类策略数据在完整验证后才共同发布缓存，损坏配置、null 元素与启用的非法正则不会静默跳过；明确保存空数组及既有模型失败策略保留。范围与裁剪验证限制见 [策略故障边界](TOOL_POLICY_SECURITY.md)。

这项修复不覆盖全部数据库错误、其他工具表、模型网络客户端或操作系统沙箱；完整工程/真实数据库、认证 PR #19 和供应链 PR #15 仍各自待验收。
